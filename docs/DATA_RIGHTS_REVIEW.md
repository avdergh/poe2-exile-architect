# 发布前数据权利风险评估

核查日期：2026-09-15。范围：当前工作区的发布文档、Git 跟踪数据、打包入口及公开来源条款。
这是工程发布风险评估，不是特定司法辖区的律师法律意见；未逐条审核所有知识正文，也未完成 Git 历史与所有 Release 资产的内容审计。

## 结论

**正常导出单个 PoB 并分析，与批量镜像站点或再分发完整角色集合，应分别判断。**

poe.ninja 官方文档明确引导用户通过“Copy PoB code”导出角色并在 Path of Building 中查看配置。
因此，不能仅凭站点通用条款，将正常的单个 BD 导入分析直接认定为未经允许的整站数据搬运。
[poe.ninja 的 PoB 配置说明](https://poe.ninja/docs/pob-configuration)

用户最新确定的发布目标是：Research/Create 的构筑研究输入只接收用户指定的 PoB code，
公开知识库不附案例来源信息，包括来源 hash。此前建议“公开保留最小来源绑定”不符合这一要求，
已在第 6 节纠正；当前仍是待实施的发布边界，不代表已有种子已去除来源。

这一区分并不支持“一切风险已经消失”的确定性法律结论。独立机制分析不应自动等同于侵权，
删除来源字段也不自动改变所分发内容的权利性质。具体应看公开内容是否复制受保护表达、游戏美术或完整资料，
以及实际使用方式；本报告不把所有净化知识一概认定为需要逐条取得许可。

## 1. poe.ninja：访问权限与再分发权限

poe.ninja 的通用服务条款写有个人、非商业、临时浏览用途的有限下载许可，以及复制、公开展示、转移和镜像限制。
条款页面标注更新日期为 2024-09-28，并选择丹麦法律。其文字并非仅列“商用”和“大批量搬运”两项，
但应用于具体单 BD 工具时，也应同时考虑上述官方导出功能和实际用途，不能机械套用为一概禁止。
[poe.ninja 服务条款](https://poe.ninja/terms)

项目采取的净化与改写方式会影响具体风险，但不解决采集行为本身的合同权限。注明来源、免费开源、没有保留账号名或没有保存完整 PoB，均不自动消除这一问题。
是否存在另行授权、合作约定或可适用的法定例外，需要确认，不能把“研究用途”直接当作豁免。

除了版权，还需评估数据库权：欧盟数据库指令对满足条件的数据库保护实质部分提取/再利用，也涉及反复、系统性抽取非实质部分。
该规则是否适用于具体数据、抽取方式及项目所在地，需专业复核；单条游戏事实未必受版权保护，不代表批量抽取一定不受限制。
[欧盟数据库指令 96/9/EC，第 7 条（官方索引）](https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=CELEX:31996L0009)

本次直接读取指令正文遇到网站验证，相关条文仅核对到官方检索摘要，尚未完成全文适用性复核。

## 2. GGG、Wiki 与上游代码是不同权利层

- **GGG 数据与美术**：GGG 条款保留对游戏相关内容的权利，并限制许可外的复制、存储、分发及数据提取。Website API 使用另受官方技术政策约束；不能把代码的 MIT 许可延伸为游戏素材许可。[GGG 条款，第 4、6、7、22 条](https://www.pathofexile.com/legal/terms-of-use-and-privacy-policy)
- **官方接口不是可立即替换的无限制采集渠道**：官方开发文档限制可用资源、要求遵守限流和第三方声明；本次查询时新应用注册标为暂不可处理。改用官方 API 仍需核对权限与资源覆盖。[GGG 开发者文档](https://www.pathofexile.com/developer/docs)
- **Wiki 正文与图片**：`server/live/wiki.py` 指向 poe2wiki.net，并声明 `CC BY-NC-SA 3.0`。本次直接读取该站版权页返回 403，未独立确认其当前全文。应逐来源核对署名、非商业、相同方式共享及图片的单独许可；不能改标 MIT，也不能以另一 Wiki 的条款代替确认。有关该许可证的要求见 [CC BY-NC-SA 3.0 法律文本](https://creativecommons.org/licenses/by-nc-sa/3.0/legalcode.en)。
- **上游软件**：仓库 [LICENSE](../LICENSE) 保留了 Max Wilk 的 MIT 声明；[PoB 固定依赖](../pob/PINNED.md)与[转换 provider](../providers/poe2-build-converter/UPSTREAM_LICENSE.txt)有各自来源/许可说明。须保留代码声明，另外核对其随附数据和美术的权利范围。

账号、角色标识和可关联到个人的活动数据还可能涉及隐私义务。去标识化有帮助，但可回链的来源标识不能直接视为匿名；本次不据此认定所有构筑数据均属个人数据。

## 4. schema 6→7 差异与修复结果

初次运行现有只读审计：

```powershell
uv run python scripts/audit_public_research_memory.py --db data/mature_build_learning/release.sqlite
```

结果曾为 `blocked / research_schema_version_mismatch`：种子 schema 为 **6**，代码要求 **7**。
追溯确认旧种子元数据的生成时间为 **2026-09-05 08:48 UTC**，版本 `0.1.66`；
`research_contracts.py` 的 schema 7 已在 **2026-09-09 02:53 +08:00** 的 `a124c7b` 提交中存在。
它不是本次检查前 24 小时内的变更，根因是旧发布种子未随运行合同刷新，而不是代码缺少迁移路径。

schema 6 已将正文与记录绑定分离；schema 7 进一步给每项来源声明增加 `source_claim_key`、精确
`record_id` 和 `binding_issue`，让同来源、同主题的不同条件分支并存，并按具体记录与 projection 绑定证据。
这不是仅修改版本号；迁移还依据现有精确证据修正派生来源列表、引用与计数，不补造来源或提升旧证据权限。

2026-09-15 已使用现有 `build_release_seed` 在隔离副本上迁移、校验，再原子替换仓库中的种子，
更新为 schema **7**、种子版本 **0.1.67**。输入只使用旧发布种子，没有纳入维护者当前私有知识库。
修复同时发现并更正打包时错误刷新 `last_seen_at` 的行为：发布日期保存在种子元数据，知识原有的观察时间不变。

验证结果：

- 679 条深度知识、468 条 Pattern、54 个 Family、485 条边、502 条观察全部保留。
- 深度知识的 ID、标题/正文、来源版本、状态、projection、创建/观察/验证时间均保留；
  22 条记录的安全引用缓存及 1 条记录的来源缓存/计数按精确声明纠正，其中来源数由 2 改为 1。
- 681 项来源证据、163 条补丁复核原有字段均未改写；新声明绑定无缺口。
- SQLite 完整性、外键及 release seed 校验通过；只读审计现返回 `publishable`。
- 37 项迁移与发布种子相关回归通过，包含“打包不得刷新知识观察时间”的回归验证。

`publishable` 表示程序内的数据筛选与 copy-safety 结果，**不是法律上的可分发结论**。
本次只修复仓库内种子与打包脚本，尚未执行对外发布。

## 5. 建议的发布顺序

1. **建立来源授权清单**：按数据集记录来源、采集方式、条款日期、拟发布内容、许可范围、署名要求、能否用于商业场景及撤回办法。缺授权的项目明确标待确认。
2. **对范围不明确的使用单独确认**：例如仍保留自动批量采样，或拟分发包含站点材料的数据集时，可向 poe.ninja 说明范围、频率、保存内容与分发方式，寻求明确答复。不能把此项自动变成每次用户指定 PoB 分析的前置审批。本次未代发联系消息。
3. **先确定数据范围，再制作发布版本**：未经确认的数据保持私有，或从新发布快照及其历史中排除。不能把“安装时改为自动下载”当作规避授权的办法。
4. **保留代码许可，另写准确的数据声明**：只有自己拥有或被许可转授的内容才可选用数据许可证。原创机制分析、第三方引用与图片分别标识；来源追溯资料可放在受控的许可登记中，不为署名破坏产品的 raw-free 聊天/记忆合同。
5. **检查全部分发面**：Git refs/历史、Release、LFS、插件归档、演示文件、测试夹具及数据库残留。涉及删除历史时先备份并单独确认操作范围。
6. **独立完成技术验收**：在已确定授权范围的数据上重新构建、审计，并用干净用户目录验证安装与功能。删种子后的兼容性不能用现有安装成功推定。

README 中使用原创结构示意和无游戏美术的阅读器演示；它们不附第三方完整 BD，不展示未经验证的 DPS 或通关效果。
schema 差异已按第 4 节修复；数据授权仍需单独解决，不能把“README 已规范化”当作“整个仓库已可安全公开”。

## 6. 用户明确的公开版边界（待实施）

- **研究输入**：公开版 Research 和 Create 涉及的外部构筑研究，只接受用户明确指定的 PoB code，
  来源由用户决定，不再提供自动案例采样或根据网页链接抓取角色的研究入口。
  这是对研究材料入口的约束，不把 Create 原有的目标等级、职业等生成需求替换成 PoB code。
- **公开知识库**：发布知识结论，不带来源站点、URL、账号/角色、案例 ID、来源 hash、采集历史，
  也不通过嵌套字段、关联表或正文引用重新暴露这些来源信息。
- **本地状态**：必要的导入查重数据留在用户本地；维护者已有的来源关联与运行记录不随公开知识包分发。

实现时应让入口限制在 MCP 服务端与打包工具清单生效，并同步 skills/README。
公开知识需要独立的导出格式和读取合同：当前运行库仍依赖来源绑定进行案例选择、证据计数与修订，
不能仅删除 SQLite 来源行后继续声称原来源校验已通过。这是迁移工作，不是要求公开版保留来源字段。
可保留不识别案例的知识自身 ID、适用游戏版本与条件；依赖私有来源才能核验的声明，需要在公开读取合同中重新定义权限。

当前种子的 74 项来源 hash 尚在；本节已纠正为用户要求的零来源信息发布目标，未实际删除数据或更改接口。
